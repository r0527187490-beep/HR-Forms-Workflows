## 🎯 סקירה כללית

`hakamat-tfasim` הוא פרויקט לפיתוח מערכת לבניית תבניות וטפסים.

המערכת מחולקת לשני חלקים עיקריים:

- **Frontend** — ממשק המשתמש, המאפשר עבודה מול המערכת באמצעות דפדפן.
- **Backend** — שרת האפליקציה, האחראי על צד השרת ועל חשיפת ממשקי API.

ההפרדה בין שני החלקים מאפשרת פיתוח, תחזוקה והרחבה של המערכת באופן מודולרי.

README זה מתמקד בצד הלקוח בלבד. הוראות ההתקנה, ההגדרה וההרצה של השרת נמצאות בקובץ ה־README של תיקיית `Backend`.

> **חשוב:** המאגר פרטי. יש לוודא שקיימת הרשאת גישה לפני ניסיון לשכפל את הפרויקט.

## 📁 מבנה הפרויקט

מבנה התיקיות הראשי:

```text
hakamat-tfasim/
├── Frontend/
│   ├── src/
│   │   ├── app/
│   │   └── environments/

│
├── Backend/
│   └── TavniyotBuilder.Api/
```

### Frontend

צד הלקוח מבוסס Angular ומשמש לבניית ממשק המשתמש של המערכת.

התיקייה כוללת את קוד המקור, הגדרות האפליקציה, רכיבי הממשק, ניהול הנתיבים וקובצי הסביבה.

### Backend

צד השרת מבוסס .NET ומכיל את הפרויקט `TavniyotBuilder.Api`.

השרת מספק את שירותי ה־API שבהם משתמש צד הלקוח.

לפרטים על הרצת השרת, יש לעיין בתיעוד הנפרד של ה־Backend.

## 📦 התקנת צד הלקוח (Frontend)

```bash

```

### שלב 2 — הגדרת חבילת nmh-core

הפרויקט משתמש בחבילה פנימית בשם `nmh-core`, המסופקת כקובץ מקומי בפורמט `.tgz`.

החבילה אינה זמינה ב־npm הציבורי, ולכן יש לקבל אותה מהצוות לפני התקנת התלויות.

יש לבדוק את ההגדרה המתאימה בקובץ:

```text

```

אם החבילה מוגדרת באמצעות נתיב מקומי שמתחיל ב־`file:`, יש לוודא שהנתיב מצביע לקובץ הקיים במחשב.

אם הנתיב אינו מתאים לסביבת העבודה המקומית, יש לעדכן אותו בהתאם לצורך, בלי להעלות שינוי מקומי שאינו מיועד לשיתוף.

### שלב 3 — התקנת התלויות

יש להריץ מתוך תיקיית `Frontend`:

```bash
npm install --legacy-peer-deps
```

הדגל `--legacy-peer-deps` משמש להתמודדות עם דרישות Peer Dependencies שאינן תואמות לחלוטין בין חלק מהחבילות בפרויקט.

לאחר השלמת ההתקנה, יש לוודא שלא הופיעו שגיאות המונעות את הרצת האפליקציה.

## 🔐 מערכת ההתחברות והאבטחה

הפרויקט משתמש בספריית `nmh-core` לצורך שילוב מנגנון ההתחברות וההגנה על נתיבי המערכת.

### הגדרת שירותי ההתחברות

המודול `NMHCoreModule` והשירות `NMHCoreConfigService` מוגדרים בקובץ:

```text
Frontend/src/app/app.config.ts
```

יש לשמור על ההגדרות הנדרשות של ספריית ההתחברות בהתאם למבנה הקיים בפרויקט.

### הגנה על נתיבי המערכת

הפרויקט משתמש ב־`AuthGuard` כדי להגן על נתיבי האפליקציה.

בעת הוספת נתיב חדש, יש להוסיף את מנגנון ההגנה המתאים להגדרות הנתיב.

דוגמה עקרונית:

```typescript
{
  path: 'example',
  canActivate: [AuthGuard],
  loadComponent: () =>
    import('./example/example.component')
      .then(m => m.ExampleComponent)
}
```

יש להתאים את הנתיב ואת הרכיב למבנה האמיתי בפרויקט.

### הצגת תוכן לאחר התחברות

בקובץ `app.html` נעשה שימוש בתנאי המבוסס על `authService.Token`, בהתאם למנגנון ההתחברות של הפרויקט.

יש לשמור על מבנה התצוגה הקיים ועל המיקום הנדרש של `router-outlet`, כדי לא לפגוע בניווט בין המסכים.

### הזרקת שירותים

בפרויקט נעשה שימוש ב־Angular Dependency Injection, ובמקומות המתאימים ניתן להשתמש בפונקציה `inject()` לקבלת שירותים.

בעת הוספת שירות או רכיב, יש לפעול בהתאם לדפוסי המימוש הקיימים בקוד.

> `AuthGuard` בצד הלקוח אינו תחליף לאימות הרשאות בצד השרת. יש לוודא שגם ממשקי ה־API מוגנים בהתאם לדרישות האבטחה של המערכת.

### תיעוד ה־Backend

README זה מתאר את צד הלקוח בלבד.

לצורך התקנה והרצה של השרת, הגדרת משתני סביבה, חיבור למסד נתונים או טיפול בתקלות בצד השרת, יש לעיין בתיעוד הנמצא בתיקיית `Backend`.

### שמירה על המאגר

מומלץ לבצע שינויים בענפי עבודה נפרדים, לבדוק את הקוד לפני יצירת Pull Request ולוודא שהשינויים אינם פוגעים בפונקציונליות קיימת.

---

## 📌 סיכום

הפרויקט `hakamat-tfasim` מבוסס על הפרדה בין ממשק משתמש ב־Angular לבין שרת API ב־.NET.

כדי להתחיל לעבוד:

1. יש לוודא הרשאות גישה למאגר.
2. יש לשכפל את הפרויקט לענף המתאים.
3. יש להגדיר את חבילת `nmh-core` המקומית.
4. יש להתקין את התלויות של צד הלקוח.
5. יש להגדיר את כתובת ה־API.
6. יש להפעיל את ה־Backend.
7. יש להריץ את Angular באמצעות `ng serve`.
8. יש לפתוח את האפליקציה בכתובת `http://localhost:4200`.

בהצלחה בפיתוח ובתחזוקת המערכת!
